# wgate — design

Multi-tenant WireGuard gateway for the personal k8s cluster (hub k8s-master,
37.205.11.119). Addresses come from one global pool, so nothing ever collides. The
global admin gives each tenant (company) blocks of the pool; inside them the tenant
runs **networks** — each its own WireGuard interface — and assigns devices to them.
Access is default-deny and enforced per packet on the hub. Tenant admins manage
access inside their tenant; only the global admin connects tenants (federation).

## Why our own tool

| Tool | Blocker |
|---|---|
| Defguard | The firewall/ACL is a paid feature (Business; the free tier allows 10 users and 1 location) |
| Headscale, NetBird | Need their own client; we need plain WireGuard |
| wg-portal | No ACL. Limiting which interface a user may provision on works only through LDAP filters |

## Decisions

- Clients: plain WireGuard (Tailscale is out of scope)
- **Global pool** `10.50.0.0/16` (config, a list of CIDRs; phase 3 adds wg0's
  `172.16.16.0/24`). The global admin assigns disjoint **blocks**
  to tenants; tenants carve **networks** out of their own blocks. Tunnel addresses can
  therefore never overlap.
- **Network** = named IP range + its own interface `wg-<slug>` + UDP port. Up to 99
  networks in total: ports `51800–51899`, `51820` reserved for `wg0` (phase 3). Slugs
  are globally unique, `[a-z0-9-]{1,11}`, alphanumeric at both ends.
- **Peer** = a device's membership in a network: its own keypair, IP from the
  network's range, config and endpoint port. A device (a user's laptop, router, …)
  can be in several networks, one tunnel each; revoking one membership never touches
  the others.
- **Routers**: a peer may carry routed subnets (a LAN behind it). Hosts on that LAN
  have the router peer's access ("visibility via the router"). Routed subnets must be
  **globally** unique (no overlap with the pool or any other routed subnet) because
  the hub has one routing table; the API rejects overlaps. They must also lie inside
  `routed_space`, a global-admin allowlist (config; default the private ranges), and
  never cover the pool or reserved infrastructure (node networks, the SNAT source): a LAN becomes tenant space, which the hub refuses as
  a source on non-wg interfaces, so `128.0.0.0/1` would cut off the internet. 1:1
  NETMAP of a colliding LAN into a pool block is the planned extension, not built
  now.
- **Default deny everywhere**, even between members of one network. A per-network
  `mesh` flag (default off) lets members reach each other.
- **Roles**: global admin (everything), tenant admin (networks inside own blocks,
  device membership, routers, rules between own networks, outbound to external
  destinations within the tenant's ceiling), user (owns devices; phase 2: adds own
  peers). Networks replace the earlier groups; there are no per-user rules.
- **Federation** (global admin only): network A may open to network B on proto+ports.
  It alone suffices for cross-tenant access; tenant admins cannot create or widen it.
- **Inbound from outside the pool** (a k8s pod network, a host on wg0, the master
  itself): global admin grants `source CIDR → network` on proto+ports. No implicit
  trust for wg0 or the master.
- Login: OIDC, **one IdP per tenant**; the global admin logs in through their own.
- Peer keys: generated by the server and shown once (never stored), or the user pastes
  their own public key
- Peers never expire; revocation is manual and takes effect immediately
- Runs on k8s-master as systemd, independent of k8s; the portal is published through
  Traefik as `vpn.mmik.cz`
- `wg0` (admin infra) stays with wireguard-ui in phases 1–2 and is imported in phase 3
- First tenants (nexial, krcmar): one network each, reaching the k8s API
  `172.16.16.1:6443` plus ICMP to the nodes `172.19.9.10–12`. Isolation between
  tenants inside k8s is out of scope (flannel does not enforce NetworkPolicy)

## Architecture

One binary, `wgate`, with two subcommands that run as two systemd units:

```
                 Traefik (k8s, vpn.mmik.cz) ──► 172.19.9.10:8470
                                                    │
 ┌─ k8s-master ─────────────────────────────────────┼────────────────────┐
 │  wgate server  (user wgate, unprivileged)        ▼                    │
 │    Axum REST + embedded Vue UI, OIDC, writes the desired state ──┐    │
 │                                                                  │    │
 │  wgate agent   (root, CAP_NET_ADMIN only)                        │    │
 │    LISTEN wgate_changed + reconcile every 60 s                   │    │
 │    ├─ netlink: wg-<slug> interfaces, peers, routes               │    │
 │    └─ nft: table inet wgate (atomic replace)                     │    │
 └──────────────────────────────────────────────────────────────────┼────┘
                                                                    ▼
                                         Postgres on the db VPS (172.19.9.2)
                                         database wgate; roles wgate (rw),
                                         wgate_agent (read + hub_key, agent_status)
```

- The publicly reachable process has no root and no `NET_ADMIN`. The agent has no
  HTTP listener.
- **Hub private keys** (one per network) are generated by the agent in
  `/var/lib/wgate/keys/<iface>.key` (0600) and never leave the host. The agent writes
  only the public key to the DB.
- **DB outage:** the kernel keeps the last applied state (interfaces, peers, nft), so
  the VPN keeps running. Only changes stop.
- **k8s outage:** the VPN keeps running; only the portal is unavailable.

## Data model (Postgres, SeaORM)

```
tenant        id, slug (unique), name, disabled_at
tenant_block  id, tenant_id, cidr                 # global admin; inside the pool, disjoint
                                                  # id = claim order: on a conflict the older wins
network       id, tenant_id, slug (unique → wg-<slug>), name,
              cidr (inside one block of its tenant, disjoint from its other networks),
              port (unique, 51800–51899 except 51820), mesh bool, disabled_at
                                                  # hub address = first host of cidr
oidc_provider tenant_id NULL (= global admin), issuer, client_id   # secret: config file
user          id, tenant_id NULL (= global admin), email,
              oidc_sub NULL (bound on first login),
              role (global_admin | tenant_admin | user), disabled_at
device        id, user_id, name
peer          id, device_id, network_id, public_key (unique),
              ip (unique, inside the network, not the hub address),
              created_at, revoked_at
peer_route    id, peer_id, cidr                   # a router's LAN: inside routed_space,
                                                  # clear of pool/reserved, globally disjoint;
                                                  # id = claim order (older route wins)
ceiling       id, tenant_id, proto, dst_cidr, port_from, port_to
                                                  # global admin: external dsts the tenant may use
rule          id, network_id (opener), proto, port_from, port_to,
              dst_cidr NULL | target_network_id NULL (same tenant)  # exactly one
                                                  # tenant admin
federation    id, from_network_id, to_network_id, proto, port_from, port_to
                                                  # global admin, cross-tenant
inbound       id, network_id (target), source_cidr, proto, port_from, port_to
                                                  # global admin: sources outside tenant space
hub_key       network_id, public_key              # written by the agent only
audit         id, at, actor_user_id, action, target, detail jsonb
```

Ports are `NULL` for icmp. OIDC client secrets stay out of the DB, in
`/etc/wgate/server.toml` rendered by Ansible from the vault; a new tenant IdP means one
vault entry plus `make wgate`, and a DB row through the UI.

## Rights

A rule is `proto + CIDR + port range`, as an allow-list; `core::RuleSet` holds a set of
them in canonical disjoint form (CIDR ∩ CIDR, port range ∩ port range, same proto —
pure functions, covered by unit and property tests). The agent compiles the desired
state into two sets per peer:

```
addrs(peer)    = peer.ip/32 ∪ peer.routed
addrs(network) = ∪ addrs(active peers of the network)
tenant space   = pool ∪ all routed subnets

outbound(p ∈ N of tenant T) =
      (ceiling(T) ∩ external rules(N)) − tenant space       # dst_cidr rules
    ∪ addrs(M)       for each rule N → M (same tenant)       # with the rule's service
    ∪ addrs(M)       for each federation N → M
    ∪ addrs(N) − addrs(p)   if N.mesh                        # all services

inbound(p ∈ N) =
      addrs(M)       for each rule M → N and federation M → N
    ∪ source_cidr    for each inbound grant → N
    ∪ addrs(N) − addrs(p)   if N.mesh
```

- **When saving**, the API rejects an external rule the tenant's ceiling does not
  cover (422 with the uncovered part), a network target of another tenant, a network
  CIDR outside the tenant's blocks, and an overlapping routed subnet. **When
  compiling**, the intersection is computed again anyway, so narrowing a ceiling
  narrows everyone at once with no data migration.
- External rules never reach tenant space: it is subtracted, so access inside the pool
  exists only through rules between networks, mesh and federation.
- Every rule between networks yields both sides at once (the opener's outbound and the
  target's inbound); the hub checks both.
- The peer's `AllowedIPs` in the client config is `outbound ∪ inbound` addresses (so
  replies route back) plus the network's hub address (source of the hub's ICMP
  errors), minus the endpoint. A broad inbound source makes it a full tunnel. On the
  hub, the peer's `AllowedIPs` is `addrs(peer)`.
- Pods on other nodes reach tenants only if those nodes route the pool via the master
  (ansible, when the first such grant is needed).

## Enforcement on the hub — `table inet wgate`

Owned by the agent, replaced atomically (`table` + `delete table` + `table` in one
`nft -f` transaction, just like role `firewall`). It never touches the other tables.
The exact ruleset is the golden file `crates/core/tests/golden/ruleset.nft`; in short:

```nft
table inet wgate {
  set tenant_space { pool + routed LANs }
  set ingress      { iface . peer addrs }               # wg-<slug> . addrs(peer)
  set peer_addrs   { peer addrs }                      # all addrs(peer), interval
  set allow        { peer . dst . proto . dport }      # outbound
  set allow_icmp   { peer . dst }
  set inbound      { src . peer . proto . dport }      # inbound
  set inbound_icmp { src . peer }

  # who opened the connection picks the check; replies use the same sets, swapped
  #   fwd = ip saddr . ip daddr . meta l4proto . th dport, rev = the tuple swapped
  chain from_tenant           { ip daddr @peer_addrs jump tenant_to_tenant; fwd @allow accept; drop }
  chain tenant_to_tenant      { fwd @allow fwd @inbound accept; drop }      # both sides
  chain tenant_answers        { ip daddr @peer_addrs jump tenant_answers_tenant; rev @inbound accept; drop }
  chain tenant_answers_tenant { rev @allow rev @inbound accept; drop }
  chain to_tenant             { fwd @inbound accept; drop }
  chain to_tenant_reply       { rev @allow accept; drop }
  # (each chain has the same pair of rules for icmp against the *_icmp sets)

  prerouting (raw): non-wg ingress claiming a tenant source → drop;
                    wg-* ingress whose source is not a peer of that interface → drop
  input:   iifname wg-*  original → from_tenant, reply → tenant_answers, else drop
  forward: same for iifname wg-*, then oifname wg-*: original → to_tenant,
           reply → to_tenant_reply, else drop
  output:  a local socket sending as a peer (any interface) → drop; oifname wg-*:
           hub ICMP errors for
           a tracked flow accept; original → to_tenant, reply → to_tenant_reply, else drop
  postrouting: ip saddr @peer_addrs ip daddr { node_cidrs − tenant space } snat ip to 172.19.9.10
}
```

- **Elements must be disjoint.** nft rejects an interval element that overlaps an
  existing one ("File exists"), even when one contains the other. `core` therefore
  keeps rights in a canonical disjoint form (`RuleSet`) and renders them as
  non-overlapping boxes, e.g. `tcp 10.0.0.0/8 80-90` + `tcp 10.1.0.0/16 85-100`
  become three elements. Peer addresses are globally unique (pool + unique routed
  subnets), so elements of different peers never overlap. The inet family needs
  `snat ip to`.
- **Every packet to or from a peer is checked against the current sets**, in both
  directions, with no `ct state established` shortcut. On vpsFree LXC the host owns
  conntrack (`conntrack -D` may not work), so revocation must not depend on clearing
  it; conntrack only picks which check applies (`ct direction`). Untracked or invalid
  packets hit the drops.
- **No related-ICMP shortcut**: ICMP errors can carry payload and match flows that
  outlive a revocation, so they pass only where the icmp sets allow the host pair.
  Only ICMP errors the hub itself generates for a tracked flow go out unchecked.
  Trade-off: PMTU/unreachable errors from hosts a peer has no icmp right to are
  dropped; keep tunnel MTUs at the WireGuard default.
- **A peer's addresses are believed only on its own network's interface**
  (`@ingress`); WireGuard additionally drops packets whose source is outside the
  sending peer's `AllowedIPs` (its /32 + routed subnets). So neither a peer nor a
  leftover or misconfigured `wg-*` interface can pose as another peer. A tenant source
  arriving on any other interface, or sent by a local socket, is spoofed and dropped.
- Device-to-device is told apart by `@peer_addrs`, not by the pool: a network's hub
  address is in the pool but is no peer, so hub-opened connections (an inbound grant
  with the hub address as source) work.
- Rules apply to hub-local addresses too (input/output hooks); that is how
  `tcp 172.16.16.1/32 6443` reaches the k8s API. A broad ceiling (e.g. `0.0.0.0/0`)
  therefore also opens the hub's own services on those ports. Keep ceilings specific.
- A peer whose network is outside the pool or overlaps an older network, whose
  address is not a peer address of its network, or that claims an address an older
  peer already holds, is left out of the sets (fail closed) and reported; the older
  holder keeps working. The DB constraints should make this impossible.
- Inbound grants take sources outside tenant space only, plus hub addresses; an
  in-pool source is clipped away.
- A drop in any base chain is final, so iptables' `-i wg0 -j ACCEPT` (wg-quick) does
  not affect us.
- Role `firewall` (ansible) adds `iifname "wg-*" accept` to its input chain and
  `iifname/oifname "wg-*" accept` to its forward chain, leaving the decision to this
  table. The public ports `udp 51800–51899` go into `firewall_public_udp`.

## Revocation (immediate)

| Action | Agent does |
|---|---|
| Revoke a peer | `wg set wg-<slug> peer <pk> remove` + remove its tuples and routes |
| Remove a device / disable a user | the same for all their peers |
| Change rules, ceilings, federations or inbound grants | recompile the sets (atomic replace) |
| Disable a network | delete the interface `wg-<slug>` + its tuples |
| Disable a tenant | the same for all its networks |

Order: wg peer first, then nft. Either step alone already cuts traffic off. The server
does `NOTIFY wgate_changed` in the same transaction as the change, so a delay comes
only from the agent loop (milliseconds). The 60 s reconcile backs up a lost
notification. The UI shows "applied", taken from the agent's `applied_revision`.
Other peers are unaffected; the interface never restarts.

## Portal (UI + API)

- Login: the user picks a tenant (or types an email → domain → tenant), then goes
  through the tenant's OIDC (PKCE). The match is `(issuer, email)` → a pre-created
  user, and the first login binds `oidc_sub`. Afterwards the match is only
  `(issuer, sub)`. An unknown user gets 403, with no auto-provisioning.
- Session: an HttpOnly cookie with a signed session ID; sessions live in Postgres.
- User: their devices and peers; "add to network" (server keypair → config + QR once /
  or paste a public key → config without PrivateKey), revoke.
- Tenant admin: networks (inside own blocks, mesh flag), membership, routers and
  routed subnets, rules (with the ceiling check), the tenant's peers, its audit log.
- Global admin: tenants, blocks, ceilings, federations, inbound grants, everything a
  tenant admin can do in every tenant, the whole audit log.
- Client config: `Endpoint = 37.205.11.119:<network port>`, `AllowedIPs` as in Rights,
  `PersistentKeepalive = 25`. No DNS is pushed.
- Stack: Axum, SeaORM, `openidconnect`, Vue 3 + TS + Vite + Tailwind + Pinia, embedded
  into the binary (`rust-embed`).

## Deployment (repo ansible)

- New role `wgate` in `site.yml` (tag `wgate`, a host service like wireguard-ui):
  - pinned release binary + sha256
  - user `wgate`, two units, `/etc/wgate/{server,agent}.toml` from the vault
- Postgres: database `wgate` + roles in `group_vars/pg` (`pg_databases`); passwords via
  `make pg-password-new ROLE=wgate` / `ROLE=wgate_agent`.
- `manifests/infra/services`: Service + EndpointSlice → `172.19.9.10:8470`, Ingress
  `vpn.mmik.cz` + cert.
- Role `firewall`: `iifname/oifname "wg-*"` delegation + `firewall_public_udp`
  `51800–51899`.
- wireguard-ui: nothing by default. A wg0 client named as the source of an inbound
  grant needs the target's addresses in its `AllowedIPs`, added by hand.
- Docs: README (a VPN section), `.claude/CLAUDE.md` (exception: the agent owns
  `table inet wgate`).

## Phases

1. **MVP:** core + agent + server with global-admin login only. The global admin
   creates tenants, blocks, networks, users, devices, peers, ceilings, rules and
   hands out configs. Role `wgate`, firewall, ingress. Onboard nexial and krcmar.
2. **Self-service:** tenant OIDC, the tenant-admin role, users add their own peers,
   audit log in the UI.
3. **wg0 under wgate:** `172.16.16.0/24` joins the pool as the block of tenant
   `miksa` and wg0 becomes its network "miksa" (port 51820, the existing hub key, read
   from `/etc/wireguard`, never from the DB). Import the wireguard-ui peers: the
   infra ones (nodes, dbhosts, the Turris as a router with 192.168.0.0/23, admin
   devices) stay in "miksa"; many external devices move to other tenants/networks
   instead (new peer, new IP and config there, old wg0 peer removed); node configs
   from wgate for ansible (`wg_peer`, `wireguard`); switch off wireguard-ui. Cutover
   over public SSH 22 (it stays open on all nodes as the fallback).
4. **Later:** 1:1 NETMAP for colliding routed LANs; per-user k8s tokens instead of the
   shared `user` SA; optional Tailscale.

## Tests

- **Unit** (`core`): rule intersection (+ proptest), allocators (blocks, network CIDRs,
  peer IPs, ports), compile of the desired state into per-peer sets, nft and
  client-config rendering (golden files).
- **Integration** (`server`): REST + Postgres in a container. Covers ceiling coverage,
  tenant boundaries, the peer lifecycle, revocation → NOTIFY, and OIDC against a mock
  IdP.
- **Netns** (`make test-netns`, root/CI): the ruleset against real packets (veth links
  named `wg-*`), then the agent with real wg interfaces: two tenants and federation,
  mesh on/off, a router LAN, inbound from outside the pool, ping/TCP allowed vs.
  denied, revocation during a live TCP stream (it must stop).

## Risks

- **LXC:** additional wg interfaces + nft concatenated interval sets: nft 1.1.3, kernel
  6.12 on the master, `/dev/net/tun` present. Verify in phase 1 with a smoke test on the
  master (an interface + a set).
- **Hub = SPOF** (already the case today with wg0).
- **Phase-3 cutover:** Ansible reaches the hosts over wg0. Fallback: public SSH.
- **Routed LAN collisions** are rejected, so some home LANs must be renumbered until
  NETMAP exists.
