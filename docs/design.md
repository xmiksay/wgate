# wgate — design

Multi-tenant WireGuard gateway for the personal k8s cluster (hub k8s-master,
37.205.11.119). Each company gets its own WireGuard network. Rights are tiered
(company ⊇ group ⊇ user) and the hub enforces them per packet. Users add their own
devices after logging in through their company's OIDC provider.

## Why our own tool

| Tool | Blocker |
|---|---|
| Defguard | The firewall/ACL is a paid feature (Business; the free tier allows 10 users and 1 location) |
| Headscale, NetBird | Need their own client; we need plain WireGuard |
| wg-portal | No ACL. Limiting which interface a user may provision on works only through LDAP filters |

## Decisions

- Clients: plain WireGuard (Tailscale is out of scope)
- Scale: up to 10 companies, a few dozen users, several devices per user
- Admin creates companies, groups and users and sets their rights; users add their own devices
- Rights: company = ceiling, then group, then user (finest); never more than the company has
- Login: OIDC, **one IdP per company**; the admin logs in through their own provider
- Device keys: generated by the server and shown once (never stored), or the user pastes their own public key
- Devices never expire; revocation is manual and takes effect immediately
- Topology: one interface per company `wg-<slug>`, subnet `10.50.<n>.0/24`, UDP `51830+n`
- Runs on k8s-master as systemd, independent of k8s; the portal is published through
  Traefik as `vpn.mmik.cz`
- `wg0` (admin infra) stays with wireguard-ui in phase 1 and is imported in phase 3
- What a company can reach in phase 1: the k8s API `172.16.16.1:6443` plus ICMP to the
  nodes `172.19.9.10–12`. Isolation between companies inside k8s is out of scope
  (flannel does not enforce NetworkPolicy)

## Architecture

One binary, `wgate`, with two subcommands that run as two systemd units:

```
                 Traefik (k8s, vpn.mmik.cz) ──► 172.19.9.10:8470
                                                    │
 ┌─ k8s-master ─────────────────────────────────────┼────────────────────┐
 │  wgate server  (user wgate, unprivileged)        ▼                    │
 │    Axum REST + embedded Vue UI, OIDC, writes the desired state ──┐    │
 │                                                                  │    │
 │  wgate agent   (root, CAP_NET_ADMIN only)                        │    │
 │    LISTEN wgate_changed + reconcile every 60 s                   │    │
 │    ├─ netlink: wg-<slug> interfaces, peers                       │    │
 │    └─ nft: table inet wgate (atomic replace)                     │    │
 └──────────────────────────────────────────────────────────────────┼────┘
                                                                    ▼
                                         Postgres on the db VPS (172.19.9.2)
                                         database wgate; roles wgate (rw),
                                         wgate_agent (read + hub_keys)
```

- The publicly reachable process has no root and no `NET_ADMIN`. The agent has no
  HTTP listener.
- **Hub private keys** are generated by the agent in `/var/lib/wgate/keys/<iface>.key`
  (0600) and never leave the host. The agent writes only the public key to the DB.
- **DB outage:** the kernel keeps the last applied state (interfaces, peers, nft), so
  the VPN keeps running. Only changes stop.
- **k8s outage:** the VPN keeps running; only the portal is unavailable.

## Data model (Postgres, SeaORM)

```
company      id, slug (unique, [a-z0-9-]{1,11} → iface wg-<slug> ≤ 15 chars), name,
             net_index (n → 10.50.n.0/24, port 51830+n), disabled_at
oidc_provider company_id NULL (= admin), issuer, client_id      # secret: config file
grp          id, company_id, name
user         id, company_id, email, oidc_sub NULL (bound on first login),
             is_admin, disabled_at
user_group   user_id, group_id
rule         id, scope (company|group|user), scope_id,
             proto (tcp|udp|icmp), dst_cidr, port_from, port_to (NULL for icmp),
             comment
device       id, user_id, name, public_key (unique), ip (unique, inside 10.50.n/24),
             created_at, revoked_at
hub_key      company_id, public_key                        # written by the agent only
audit        id, at, actor_user_id, action, target, detail jsonb
```

OIDC client secrets stay out of the DB. They live in `/etc/wgate/server.toml`, which
Ansible renders from the vault: there are at most 10 companies, so a new one means one
vault entry plus `make wgate`. The provider also gets a row in the DB through the UI.

## Rights

A rule is `proto + dst_cidr + port range`, as an allow-list. Effective rights:

```
effective(user) = company ∩ (user.rules            if the user has any
                             ∪ groups(user).rules  if the user has none but is in groups
                             else company)
```

- **When saving**, the API rejects a group or user rule that the company's rules do not
  cover (422 with the uncovered part). **When compiling**, the intersection is computed
  again anyway, so narrowing the company narrows everyone at once with no data
  migration.
- Intersection of intervals: CIDR ∩ CIDR, port range ∩ port range, same proto. This is
  a pure function, covered by unit and property tests.
- The device's `AllowedIPs` in the client config is the union of the destination CIDRs
  of its effective rights. The client routes only that; the hub enforces it anyway.

## Enforcement on the hub — `table inet wgate`

Owned by the agent, replaced atomically (`delete table` + `table` in one `nft -f`
transaction, just like role `firewall`). It never touches the other tables.

```nft
table inet wgate {
  set allow     { type ipv4_addr . ipv4_addr . inet_proto . inet_service; flags interval; }
  set allow_icmp{ type ipv4_addr . ipv4_addr; flags interval; }   # saddr . daddr

  chain tenant {
    ip daddr 10.50.0.0/16 counter drop                      # never another tenant, whatever the rules
    ip saddr . ip daddr . meta l4proto . th dport @allow accept
    meta l4proto icmp ip saddr . ip daddr @allow_icmp accept
    counter drop
  }
  chain input   { type filter hook input   priority filter - 5; iifname "wg-*" jump tenant; }
  chain forward { type filter hook forward priority filter - 5;
    iifname "wg-*" oifname "wg0" ct state established,related accept   # replies to the admin
    iifname "wg-*" jump tenant
    oifname "wg-*" iifname "wg0" accept                     # admin sees the tenants
    oifname "wg-*" ct state established,related accept      # replies to tenants
    oifname "wg-*" drop                                     # nobody else, not even across tenants
  }
  chain postrouting { type nat hook postrouting priority srcnat;
    ip saddr 10.50.0.0/16 ip daddr { 172.19.9.0/24 } snat ip to 172.19.9.10   # workers have no route back
  }
}
```

- **Elements must be disjoint.** nft rejects an interval element that overlaps an
  existing one ("File exists"), even when one contains the other. `core` therefore
  keeps rights in a canonical disjoint form (`RuleSet`) and renders each device's
  rights as non-overlapping `saddr . dst-range . proto . port-range` boxes, e.g.
  `tcp 10.0.0.0/8 80-90` + `tcp 10.1.0.0/16 85-100` become three elements.
  The inet family needs `snat ip to`.
- The tenant chain filters **every packet, with no `ct state established` shortcut**.
  On vpsFree LXC the host owns conntrack (`conntrack -D` may not work), so revocation
  must not depend on clearing it.
- `ip saddr` is trustworthy: WireGuard drops packets whose source is outside the
  sending peer's `AllowedIPs` (the device's /32), so a device cannot spoof another
  device's or another company's IP.
- A drop in any base chain is final, so iptables' `-i wg0 -j ACCEPT` (wg-quick) does
  not affect us.
- Role `firewall` (ansible) adds `iifname "wg-*" accept` to its input chain and leaves
  the decision to this table. The public ports `udp 51830–51839` go into
  `firewall_public_udp`.

## Revocation (immediate)

| Action | Agent does |
|---|---|
| Revoke a device | `wg set wg-<slug> peer <pk> remove` + remove its tuples from the sets |
| Disable a user | the same for all their devices |
| Change rules | recompile the sets (atomic replace) |
| Disable a company | delete the interface `wg-<slug>` + its tuples |

Order: wg peer first, then nft. Either step alone already cuts traffic off. The server
does `NOTIFY wgate_changed` in the same transaction as the change, so a delay comes
only from the agent loop (milliseconds). The 60 s reconcile backs up a lost
notification. The UI shows "applied", taken from the agent's `applied_revision`.
Other peers are unaffected; the interface never restarts.

## Portal (UI + API)

- Login: the user picks a company (or types an email → domain → company), then goes
  through the company's OIDC (PKCE). The match is `(issuer, email)` → a pre-created
  user, and the first login binds `oidc_sub`. Afterwards the match is only
  `(issuer, sub)`. An unknown user gets 403, with no auto-provisioning.
- Session: an HttpOnly cookie with a signed session ID; sessions live in Postgres.
- User: list of their devices, "add device" (server keypair → config + QR once / or
  paste a public key → config without PrivateKey), revoke.
- Admin: companies, groups, users, rules (with the coverage check), all devices, audit log.
- Client config: `Endpoint = 37.205.11.119:<51830+n>`, `AllowedIPs` = effective
  CIDRs, `PersistentKeepalive = 25`. No DNS is pushed.
- Stack: Axum, SeaORM, `openidconnect`, Vue 3 + TS + Vite + Tailwind + Pinia, embedded
  into the binary (`rust-embed`).

## Deployment (repo ansible)

- New role `wgate` in `site.yml` (tag `wgate`, a host service like wireguard-ui):
  - pinned release binary + sha256
  - user `wgate`, two units, `/etc/wgate/{server,agent}.toml` from the vault
- Postgres: database `wgate` + roles in `group_vars/pg` (`pg_databases`); passwords via
  `make pg-password-new ROLE=wgate` / `ROLE=wgate_agent`.
- `manifests/infra/services`: Service + EndpointSlice → `172.19.9.10:8470`, Ingress
  `vpn.mmik.cz` + cert.
- Role `firewall`: `iifname "wg-*"` delegation + `firewall_public_udp`.
- wireguard-ui: add `10.50.0.0/16` to `WGUI_DEFAULT_CLIENT_ALLOWED_IPS`, so the admin's
  devices see the tenants.
- Docs: README (a VPN section), `.claude/CLAUDE.md` (exception: the agent owns
  `table inet wgate`).

## Phases

1. **MVP:** core + agent + server with admin login only. The admin creates companies,
   users, rules and devices (and hands out configs). Role `wgate`, firewall, ingress.
   Onboard nexial and krcmar.
2. **Self-service:** company OIDC, users add their own devices, audit log in the UI.
3. **wg0 under wgate:** import wireguard-ui peers (nodes, dbhosts, Turris + 192.168.0/23,
   admin devices), node configs from wgate for ansible (`wg_peer`, `wireguard`), switch
   off wireguard-ui. Cutover over public SSH 22 (it stays open on all nodes as the
   fallback).
4. **Later:** per-user k8s tokens instead of the shared `user` SA (a revoked person
   knows that token, though without the VPN it cannot reach 6443), optional Tailscale.

## Tests

- **Unit** (`core`): rule intersection (+ proptest), the allocator for IPs/net_index,
  nft and client-config rendering (golden files).
- **Integration** (`server`): REST + Postgres in a container. Covers rule coverage, the
  device lifecycle, revocation → NOTIFY, and OIDC against a mock IdP.
- **Netns** (`make test-netns`, root/CI): the agent in a network namespace with real
  wg interfaces. Two companies, ping/TCP allowed vs. denied, revocation during a live
  TCP stream (it must stop).

## Risks

- **LXC:** additional wg interfaces + nft concatenated interval sets: nft 1.1.3, kernel
  6.12 on the master, `/dev/net/tun` present. Verify in phase 1 with a smoke test on the
  master (an interface + a set).
- **Hub = SPOF** (already the case today with wg0).
- **Phase-3 cutover:** Ansible reaches the hosts over wg0. Fallback: public SSH.
